# v0.1 设计决定

这些是 2026-11-18 记下的**决定**，不是实验结果。对应 [../03-benchmark-design.md](../03-benchmark-design.md) 第 9 节的问题 1、2、4。该节的原文保留；若决定和后文冲突，以本文件为准，并在 `docs/status.md` 说明。

模型、`B_inject`、最大步数仍然待定。没有嵌入模型的默认值。

## 1. 图臂：冻结适配器，不调用上游 dispatch

**决定。** v0.1 的图臂是一个只实现 `kb_write` / `kb_search` / `kb_read` / `kb_list` 的适配器。字段与 nvwabase `lib/fg.py` 在提交 `c9ec790a99c01641d566e38d8d7d7e6c63a24bcc`（2026-11-11，`master`）上的无类型模型一致：事实含 `title`、`description`、`doc`；意图含 `from`、`to`。搜索实现 token 重叠（标题计两次）加 `difflib` 后备，与该文件中 `recall` 的注释一致。不调用 `fgc dispatch`、`fgc auto`，不加载仓库里的 `templates/`，不启动 `nvwa`。

**理由（解释，不是测量）。** `dispatch` 会启动 `claude` 并使用上游提示模板，步数和模型默认值也在那个 CLI 里。若图臂走 dispatch、另外两臂不走，自变量就包含编排。适配器把结构留在进程内，三臂共用我们自己的代理循环。

**仍须在实现时钉死的事。** 适配器注释里写上上述提交号。上游 `master` 此后若改字段，v0.1 不跟随。不把 sapper 的 `kind` / `data` 加进这一臂。

这回答了设计文档第 9 节问题 1：允许按字段重写，并且决定就这么做。

## 2. 向量臂：先对齐证据预算，嵌入模型待定

**决定。** 三臂每次 `kb_search` 返回的证据单元数不超过同一个 `limit`，自动注入的字符或 token 不超过同一个 `B_inject`。向量臂不得因为相似度分数高就多返回几块。日志单独记录嵌入模型的名称、维度和每次查询的分数，但分数不改变返回条数的上限。

**嵌入模型：未选定。** MemGPT 论文的文档问答设置使用了 `text-embedding-ada-002`（见 [literature.md](literature.md)）。那是另一项任务、另一个年份的选择，不能当成 2026 年这个基准的推荐模型。在没有一份我们打开过、且讨论“用哪一个嵌入才不把结构比较变成嵌入比较”的来源之前，不填写具体模型名。

**可比性规则（实现约束）。**

- 返回给模型的文本按同一分词器计数。分词器在选定对话模型后确定，三臂共用，不用嵌入模型自己的分词器作为比较单位。
- 若一个证据单元超过剩余预算，三臂都截断并在日志里记截断字符数，不换下一条“更短所以更能塞进”的单元来偏袒某一臂。
- 嵌入质量的差异写进附录（模型名、维度），不写进“结构胜出”的句子。若以后要分离嵌入和质量，需另加一臂：同一嵌入、不同组织方式。v0.1 不加。

这回答了设计文档第 9 节问题 2 的前半：用共同的条数上限和注入预算控制证据量。后半（具体模型和 k 的数值）仍待定。`limit` 的数值与 `B_inject` 一起，在选定对话模型后冻结。

## 3. 交接失败时的默认顺序

**决定。** 若三臂在同一批题上的判断准确率都没有离开地板，下一步是修改共用提示词和/或 `B_inject`，然后用同一批脱敏题目重跑。不把源码交给交接代理。只有在至少一轮“改提示或预算”之后、三臂仍然一起贴着地板，才把“交接代理同时看见源码和知识库”写成一个新的实验问题，而不是悄悄改 v0.1 的主协议。

**地板的操作定义仍待定。** 在看到抽样后的标签分布之前，不写一个百分比。开跑前要写死一条规则，例如“三臂都低于该批标签的多数类比例，或失败率超过事先写下的阈值”。阈值本身还没有数。

这把设计文档第 9 节问题 4 的“倾向”收成默认顺序。该问题里“没有证据”仍然成立：这是协议选择，不是经验结论。

## 4. 选定模型之后要冻结的清单

模型名保持空白，直到有人在 `docs/status.md` 写下具体标识。选定之后、开跑之前，按顺序填完下面各项。没有填完就不开 144 次运行。

1. **模型标识。** 提供方、模型名、版本或快照日期。三臂相同。
2. **窗口。** 该版本公开文档中的上下文长度。若文档没有写，停，不估计一个数。
3. **分词器。** 与该模型对应、可在本地复算的分词器名称。API 若返回 usage，以 usage 为准；否则用这个分词器，并在每条日志里标明来源。两种来源不混成一个平均数（与设计文档第 5.2 节相同）。
4. **`B_inject`。** 写成窗口的一个明确比例或一个绝对 token 数，并说明为什么三臂在这个预算下都不能靠“把整份短文件塞进上下文”蒙混。Juliet 抽查完成后再看源码 token 与 `B_inject` 的比。比值接近 1 的题不能用来谈论长上下文（设计文档第 7 节已写）。
5. **`N_steps` 与单次输出上限。** 两个整数。超步数的运行记失败，不重跑到成功。
6. **解码。** 温度、以及提供方是否还有会改变复现的其他采样参数。没有把握就写上实际请求体。
7. **会话隔离。** 每题新的会话标识。若提供方文档没有承诺不把历史带进下一会话，在威胁节写明这一点，而不是假设隔离成立。
8. **训练泄漏。** 查该模型的公开文档或模型卡是否提到 Juliet、SARD 或 CWE 测试套件。查不到就记“未知”，不记“未泄漏”。
9. **费用上限。** 用公开价格估算 16 题 × 3 臂 × 3 次 ×（写入 + 交接）的上限。估算方法写下来。这是预算闸，不是结果。
10. **嵌入模型（仅向量臂）。** 仍可在这一步选定，但必须同时写下第 2 节的条数上限，并记录模型名。未选定时向量臂不能跑。
